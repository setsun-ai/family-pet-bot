# Как это устроено (для любопытных разработчиков)

🇬🇧 [English version](../en/how-it-works.md) · [← README](../../README.ru.md)

Небольшой бот (~1500 строк), сделанный с аккуратностью настоящего сервиса, потому что он тратит реальные деньги и пишет в реальный семейный чат. Самое интересное здесь — решения, принятые при проектировании.

## Карта

```
Telegram ──long polling──► handlers.py ─┐
Discord ───gateway───────► discord_bot.py ┴► core.py, ai.py ──► Anthropic / OpenAI REST
                              │                  ▲
            контроль доступа ◄┘                  │ файл персонажа + промпты i18n
            (security.py)                        │
                          delivery.py (Delivery: серии сообщений, не больше одного раза)
                             ├─ DeliveryService ─► Telegram sendMessage
                             └─ DiscordDelivery ─► Discord channel.send
                              ▲
scheduler.py ─► news.py (RSS)
             ├► sports.py (TheSportsDB, ESPN, upl.ua)
             └► family.py (похвала недели, дни рождения)
всё состояние ──► db.py (SQLite: владелец, чат, память, лимиты, отправки)
```

| Файл | Роль |
|---|---|
| `config.py` | Типизированные проверенные настройки; загружаются явно, а не побочным эффектом импорта. |
| `i18n.py` | Все тексты для людей и инструкции ИИ на EN и RU. |
| `handlers.py`, `menus.py` | Telegram: команды, контроль доступа, разговор, меню «/» для разных людей. |
| `discord_bot.py` | Discord: то же со слэш-командами, скрытыми ответами и без пингов. |
| `core.py` | Что говорит питомец независимо от мессенджера: памятка, /status, /check, /preview. |
| `ai.py` | Прямые асинхронные REST-клиенты, лимит расходов, понятные ошибки. |
| `persona.py` | Файл персонажа, правила эмодзи, чистка ответов. |
| `news.py`, `sports.py`, `family.py`, `scheduler.py` | Автоматические публикации: новости, матчи, похвала, дни рождения. |
| `delivery.py`, `housekeeping.py` | Отправка (не больше одного раза) и порядок в группе. |
| `db.py`, `backup.py` | SQLite с последовательными транзакциями, онлайн-копии. |

## Идеи, которые стоит позаимствовать

1. **Никто, кроме вас, не тратит ваши деньги.** До ИИ доходят только владелец, разрешённые люди и одна семейная группа. Владелец привязывается одноразовым кодом из окна запуска с ограниченным сроком действия, поэтому первый нашедший бота не сможет его захватить.
2. **Лимиты хранятся в базе, а не в памяти.** Перезапуск не должен их обнулять. Каждая HTTP-попытка учитывается *до* отправки. У новостей свой подлимит, чтобы они не съели бюджет разговора.
3. **Не повторять спорные платные запросы.** Если запрос к ИИ оборвался по таймауту, провайдер мог уже выставить за него счёт, поэтому автоматического повтора нет. Повтор бывает только при явном «попробуйте снова» (HTTP 429/5xx).
4. **Доставка «не больше одного раза».**
   - Перед отправкой публикация *резервируется* в SQLite с уникальным ключом: `("news", id_статьи)` или `("dialog", id_сообщения)`.
   - Вторая попытка находит ключ и останавливается.
   - Если Telegram не подтвердил отправку, она помечается *спорной*, и решение о повторе принимает владелец. Дубль в семейном чате хуже пропуска.
5. **Факты — из источников, голос — от модели.** ИИ не выдумывает ни новостей, ни счёта. Факты дают RSS и TheSportsDB; ИИ только выбирает историю и добавляет реплику в образе. Если ИИ недоступен, спортивные факты всё равно публикуются.
6. **Структурированный вывод.** Решение по новости запрашивается по JSON-схеме (`accept`/`reject` + текст). Невалидный JSON считается ошибкой, а не тихим «отклонить», поэтому новость не теряется из-за сбоя.
7. **Чужой текст остаётся данными.**
   - Материалы RSS, цитаты и имена передаются в JSON с пометкой *«данные, не инструкции»* (защита от prompt injection).
   - В Telegram всё уходит обычным текстом (`parse_mode=None`), так что ответ ИИ не может внедрить HTML.
8. **Порядок внутри чата, параллельность между чатами.** Блокировка на каждый чат сохраняет историю последовательной, а разные чаты не ждут друг друга.
9. **Секреты не попадают в журнал.** Форматтер журнала вырезает токен и ключи, в том числе из сообщений об ошибках библиотек.
10. **Приватность заложена в устройство.** Сообщения, не адресованные боту, отбрасываются до обращения к базе. Личные файлы персонажа называются `*.local.md` и игнорируются git.

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest        # ~100 тестов, без сети и реальных аккаунтов
python -m ruff check .
```

- Поддельная сессия Telegram записывает, что бот отправил бы.
- ИИ заменён заглушкой или обслуживается через `httpx.MockTransport`.
- Есть регрессионные тесты рискованных случаев: повторные обновления Telegram, старые сообщения после простоя, невалидный JSON от ИИ, использование базы первой версии.

CI прогоняет их на Linux, Windows и macOS при каждом push.
